# 개통일 오기재 수정 + 인도네시아(ID) 데이터 포함

## 1. 기존 고객 개통일이 잘못 들어가는 원인 (확인 완료)

DB의 `existing` 풀 개통일을 조회한 결과, 값이 다음과 같이 몰려 있습니다.

```text
2010-06-26  318건      2019-07-25  318건
2018-07-25  277건      2012-07-25  271건
2027-06-26  136건  ← 미래 날짜(불가능)
```

원본 엑셀의 `25-07-10`(연-월-일, 한국식 2자리 연도) 같은 값이 업로드 파싱에서
`일-월-연`(DD-MM-YY)으로 해석되어 **2010-07-25** 로 저장되고 있습니다.
연도와 일자가 서로 뒤바뀐 것이며, 그 결과 2027년 같은 불가능한 미래 날짜까지 생겼습니다.

### 수정 방향

- 엑셀 업로드 날짜 파싱에서 `NN-NN-NN` 형태가 들어오면 우선순위를 바꿉니다.
  - 첫 숫자가 13 이상이거나 마지막 숫자가 31 이하인 일반적 한국식 표기는 **연-월-일**로 해석
  - 명백히 일-월-연인 경우(첫 숫자 > 12 이고 마지막이 4자리 연도)만 기존 규칙 유지
  - 어느 쪽으로도 해석이 불가능하면 값을 비워두고 "형식 오류"로 집계(조용히 잘못 저장하지 않음)
- 미래 날짜(오늘 이후) 개통일은 저장 전에 거르고 오류 건수로 보고합니다.

### 기존에 잘못 저장된 데이터 복구

이미 저장된 `existing` 풀 개통일 중 뒤바뀐 패턴에 해당하는 행을
연도↔일자 되돌리기(예: `2010-07-25` → `2025-07-10`)로 일괄 보정하는 마이그레이션을 실행합니다.
되돌린 결과가 유효한 날짜가 아니거나 여전히 미래인 경우는 손대지 않고 목록으로 보고합니다.

## 2. 인도네시아(ID) 데이터 포함

`countries` 테이블에 ID(인도네시아)는 이미 활성 상태로 등록되어 있습니다.
다만 구글시트 동기화 코드에 허용 국가 화이트리스트가 4곳 있고, 여기에 ID가 빠져 있어 데이터가 걸러지고 있습니다.

- `src/lib/google-form-sync.functions.ts`
  - 허용 국가 집합 4곳(`ALLOWED_CODES`, `RECEIVED_ALLOWED`, 친구추천 `ALLOWED` 등)에 `"ID"` 추가
  - 국가명 매핑에 `INDONESIA / IDN / ID → ID` 추가
- 고객관리 화면의 국가 필터는 `countries` 테이블을 그대로 읽으므로 별도 수정 불필요
- 반영 후 다음 동기화부터 ID 데이터가 모든 풀(개통 신청자, 구글폼 신청자/인터, 친구 추천)에 들어옵니다.
  과거 시트 행도 동기화 시 재조회되므로 누락분은 자동 채워집니다.
