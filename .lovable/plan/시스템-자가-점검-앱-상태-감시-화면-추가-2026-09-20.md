# 시스템 자가 점검 (앱 상태 감시) 화면 추가

이번 "개통 완료 숫자가 안 맞는" 문제처럼, 화면에 보이는 숫자나 동작이 조용히 어긋나는 일을
사람이 발견하기 전에 앱이 스스로 잡아내도록 만듭니다.

솔직하게 먼저 말씀드리면, "이상이 생기면 앱이 알아서 코드를 고치는" 기능은 만들 수 없습니다.
대신 **이상을 즉시 발견해서 눈에 띄게 알려주고, 원인까지 짚어주는** 구조는 만들 수 있고,
실제로 사고를 막는 데는 이 방식이 훨씬 효과적입니다.

## 1. 관리자 전용 "시스템 점검" 메뉴

관리자 메뉴에 점검 화면을 새로 만듭니다. 들어가면 전체 상태가 한눈에 보입니다.

- 정상 / 주의 / 오류 세 단계로 색이 표시됨
- 각 항목마다 "무엇이 어긋났는지", "몇 건인지", "언제 확인했는지" 표시
- 문제가 있으면 해당 데이터로 바로 이동하는 링크 제공
- 수동 "지금 점검" 버튼 + 화면을 열어두면 자동 갱신

## 2. 점검 항목 (자동 검사 규칙)

### 숫자 정합성 (이번 문제 유형)
- 한패스 현황: 카드의 처리 건수·개통 완료 값과 아래 상세표·상태 분포 합계가 일치하는지
- 대시보드·채널별 성과·SLA: 각 화면의 합계와 원본 데이터 합계 대조
- 상태별 건수 총합 = 전체 건수 인지 확인

### 데이터 이상
- 미래 날짜로 들어온 개통일·접수일
- 전화번호 형식이 깨진 고객
- 담당자 없이 방치된 고객 수 (기준 초과 시 주의)
- 같은 번호가 같은 그룹에 중복 등록

### 연동 상태
- 구글 시트 5종 동기화: 마지막 성공 시각, 최근 실패 여부 (탭 이름 변경 같은 사고 즉시 감지)
- 통화 로그 수신: 최근 수신 여부와 매칭 실패 건수
- 텔레그램 웹훅·AI 자동응답: 최근 오류 건수
- 문자 발송 실패율

### 시스템
- 데이터베이스 용량·접속 포화도 (지난번 느려짐 사고 유형)
- 최근 화면 오류(빨간 화면) 발생 기록

## 3. 알림

- 오류 단계가 발생하면 관리자 화면 상단에 배지로 표시
- 심각 항목(연동 중단, 숫자 불일치)은 관리자에게 알림으로 전달
- 점검 이력이 쌓여서 "언제부터 틀어졌는지" 추적 가능

## 4. 제가 지키는 작업 규칙

기능 추가 때 같은 실수를 반복하지 않도록, 집계 화면을 만들거나 고칠 때는
카드 숫자와 상세표 합계가 맞는지 확인한 뒤 전달하는 것을 고정 규칙으로 저장합니다.

## 기술 상세

- 테이블 `system_checks`(검사 키, 상태, 메시지, 수치, 검사 시각) — 관리자만 조회, 서버만 기록
- DB 함수 `run_system_checks()`: 위 규칙들을 SQL로 한 번에 계산해 `system_checks`에 기록하고 요약 jsonb 반환.
  집계 화면 검증은 `stats_hanpass_dashboard` 등 기존 RPC 결과와 원본 합계를 비교
- 연동 상태는 `call_log_ingest`, `google_form_submissions`, `sms_logs`, `ai_reply_logs`, `telegram_messages`
  최신 레코드 시각/실패 건수로 판정
- 화면 `src/routes/system-health.tsx` + `src/hooks/use-system-health.ts`, `AppSidebar` 시스템 그룹에 관리자 전용 메뉴
- 자동 실행: 화면 열람 시 + `pg_cron`으로 1시간 간격 `run_system_checks()` 호출
- i18n `systemHealth.*` (ko/en), `bunx tsgo --noEmit` 통과 확인
