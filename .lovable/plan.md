# 텔레그램 상담 – 담당자 동시 답장 방지 (상담 선점/잠금)

현재는 답장을 보내는 순간에야 담당자가 배정되어, 두 직원이 같은 대화를 동시에 열고 각자 답장할 수 있습니다. 대화를 "선점(claim)"하는 잠금 구조를 추가해 한 번에 한 명만 답장하도록 만듭니다.

## 동작 방식

1. 직원이 대화를 열면 자동으로 선점 시도
   - 담당자가 없는 대화: 그 직원이 담당자로 즉시 배정되고 잠금 시각이 기록됩니다.
   - 이미 다른 직원이 담당 중인 대화: 읽기 전용으로 열리고 상단에 "자수르 님이 상담 중입니다" 배너가 뜹니다. 입력창은 비활성화되고 "인계받기" 버튼만 노출됩니다.
2. 잠금은 3분 유효, 화면을 보고 있거나 입력 중이면 자동 연장됩니다. 3분 이상 활동이 없으면 자동 해제되어 다른 직원이 이어받을 수 있습니다.
3. 인계받기: 다른 직원의 잠금이 살아 있어도 버튼을 눌러 강제 인계 가능(확인창 표시). 인계 시 기존 담당자 화면은 실시간으로 읽기 전용으로 전환됩니다.
4. 목록에도 "🔒 상담 중 · 파란기즈" 표시를 넣어 열기 전에 알 수 있게 합니다.
5. 마지막 안전장치: 전송 시점에 서버가 다시 한 번 잠금 소유자를 확인합니다. 그 사이 다른 사람이 인계했다면 전송을 막고 "다른 담당자가 인계했습니다. 새로고침 후 확인하세요"를 안내합니다(중복 발송 원천 차단).
6. 완료 처리하거나 대화 목록에서 나가면 잠금이 해제됩니다.

## 기술 상세

- DB: `telegram_chats`에 `locked_by uuid`, `locked_at timestamptz` 추가. 잠금 유효기간은 서버에서 3분으로 판정.
- 서버 함수(`src/lib/telegram.functions.ts`)
  - `claimTelegramChat({ chatRowId, force })`: 조건부 UPDATE (`locked_by is null OR locked_by = me OR locked_at < now()-3min` 또는 `force`)로 원자적 선점. 성공 시 `assigned_operator_id`도 함께 설정. 실패 시 현재 점유자 정보 반환.
  - `heartbeatTelegramChat`: 기존 `setTelegramOperatorTyping`을 확장해 `locked_at`도 갱신(30초 주기 + 타이핑 시).
  - `releaseTelegramChat`: 잠금 해제(대화 전환/완료 처리/언마운트 시 호출).
  - `sendTelegramReply` / `sendTelegramMedia`: 전송 전 잠금 소유자 검증, 불일치 시 명확한 에러 반환.
- UI(`src/routes/telegram.tsx`): 대화 선택 시 claim 호출, 잠금 상태에 따라 입력창 비활성화 + 배너 + 인계 버튼, 목록 배지 추가. 기존 realtime 구독으로 잠금 변화가 즉시 반영되게 합니다.
- 웹훅 AI 로직에는 영향 없음(기존 `operator_typing_at` 기반 억제 유지).
