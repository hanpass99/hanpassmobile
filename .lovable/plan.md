# Telegram 계정 연동 방안

## 질문에 대한 답변

봇이 아닌 **개인 Telegram 계정**을 CRM에 직접 연결하는 것은 기술적으로 가능하지만, 현재 CRM이 사용하는 **Telegram Bot API로는 불가능**합니다. 개인 계정을 사용하려면 Telegram의 MTProto 프로토콜(클라이언트 API)을 사용해야 하며, 이는 별도의 라이브러리(GramJS, Telethon 등), 전화번호 인증, 세션 키 저장, 계정 정지 리스크 등이 따라옵니다.

따라서 안정성과 보안을 위해 **기존 봇 기반을 유지하되, 팀/직원별로 봇을 분리하고 CRM에서 통합 관리하는 방향**을 추천합니다.

## 추천 방향: 봇 기반 유지 + 팀/직원별 봇 분리

현재 구조는 단일 봇으로 모든 고객 대화를 받고 있습니다. 이를 확장하여 국가/팀/담당자별로 별도 봇을 연결하고, CRM 하나에서 모든 봇의 대화를 통합 조회·답변하는 구조로 개선합니다.

```text
[고객 A] -> [CIS 봇] -> [CRM telegram_chats]
[고객 B] -> [ID 봇]   -> [CRM telegram_chats]
[고객 C] -> [공용 봇] -> [CRM telegram_chats]
              ^
              |
       CRM에서 답변 발송 (해당 봇으로 라우팅)
```

## 구현 항목

1. **다중 봇 설정 테이블 추가**
   - `telegram_bots` 테이블: 이름, bot_token, webhook_secret, 담당 팀/국가, 활성화 여부
   - 기존 `telegram_chats`, `telegram_messages`에 `bot_id` 컬럼 추가

2. **Webhook 엔드포인트 확장**
   - `/api/public/telegram/webhook/:botTokenHash` 또는 secret으로 봇 구분
   - 각 봇의 webhook URL을 개별로 등록
   - 들어오는 메시지에 bot_id를 기록

3. **CRM UI 개선**
   - 텔레그램 상담 페이지에 "봇/팀" 필터 추가
   - 채팅 목록에 어떤 봇으로 들어왔는지 표시
   - 답변 발송 시 해당 채팅의 봇 토큰 사용

4. **운영 설정 화면**
   - 관리자가 봇 추가/수정/비활성화
   - 봇별 webhook 등록 버튼

5. **기존 데이터 마이그레이션**
   - 기존 단일 봇 데이터에 기본 bot_id 할당

## 기술 상세

- Bot API는 그대로 유지하므로, 메시지 수신/발송, 미디어, AI 자동 응답, 수신 거부 등 기존 기능이 모두 유지됩니다.
- Cloudflare Worker 환경에서도 안정적으로 동작합니다.
- 개인 계정 MTProto 방식의 전화번호 인증, 세션 저장, 정지 리스크를 회피합니다.

## 제외하는 방향

개인 Telegram 계정 직접 연동(MTProto)은 아래 이유로 현재 단계에서는 제안하지 않습니다:
- Telegram 서비스 약관 위반 가능성 및 계정 정지 리스크
- 전화번호 인증과 세션 키 저장에 따른 보안/개인정보 부담
- Cloudflare Worker에서 MTProto 라이브러리 호환성 문제
- 고객 입장에서도 봇과 개인 계정의 차이를 인지하기 어려움
